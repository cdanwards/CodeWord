# Architecture overview

Codeword is a companion app for Word Assassins: players join an **operation** with a six-character code, each is secretly assigned a target and a growing set of codewords, and they try to get their target to say any of their words. See the [glossary](../../specs/glossary.md) for terms.

## Stack

| Layer | Choice |
|---|---|
| App | React Native 0.79, Expo SDK 53, Expo Router 5 (file-based routes), TypeScript strict. Scaffolded from Ignite. |
| State | Zustand (auth only) persisted with MMKV; everything else is screen state loaded from Supabase |
| Backend | Supabase: Auth, Postgres with row-level security, and Postgres functions for game logic |
| Types | Drizzle table definitions + Zod (`supabase/schema.ts`), plus hand-written types for engine results |
| Native build | Expo Continuous Native Generation: `ios/` and `android/` are generated by `expo prebuild` and not committed |

## Layers

```
screens & game views  (src/screens, src/components/game)
        │  call
        ▼
db helpers            (src/lib/database.ts)  ── case conversion, error handling
        │  supabase-js
        ▼
Supabase              tables under RLS  +  engine functions (SECURITY DEFINER)
```

- **Screens never call Supabase directly.** All table and function access goes through `db` in `src/lib/database.ts`, which converts snake_case columns to camelCase and back (see [client data flow](client-data-flow.md)).
- **Game rules run in the database.** Starting, reporting, confirming and ending happen in Postgres functions; the client only displays results and calls them. See [ADR 0002](../adr/0002-server-side-game-engine.md).
- **Auth** is Supabase Auth with the session kept on the device. See [auth and session lifecycle](auth-and-session-lifecycle.md).

## Folders

```
src/
  app/                  Expo Router routes (thin: most render a screen or a game view)
  screens/              Full screens: Login, Signup, Home (HQ), Profile (Agent), Games (case files)
  components/           Shared components (Text, Button, TextField, Screen, sheets)
    ui/                 Dossier primitives: Stamp, Folder, Sheet, TopBar, Chip, CodeBoxes, ...
    game/               One view per game state: Lobby, Mission (+ ReportSheet), IncomingReport,
                        Eliminated, Debrief
  lib/                  database.ts (all data access), auth-client.ts, network-utils.ts
  stores/               Zustand auth store
  theme/                Colors, typography, spacing, tokens
  utils/                share/clipboard, storage, dates
supabase/
  migrations/           Numbered SQL migrations (the database's source of truth)
  schema.ts             Drizzle tables, Zod schemas, TypeScript types
  database.ts           The supabase-js client
scripts/                simulate-game.mjs, agent.mjs, test-supabase.js
plugins/                Expo config plugins (splash screen, Xcode 26 fmt fix)
docs/                   This documentation
```

## Routes

| Route | Renders | Notes |
|---|---|---|
| `/` (`app/index.tsx`) | nothing | Redirects to HQ or login once auth state is known |
| `/(auth)/login`, `/(auth)/signup` | LoginScreen, SignupScreen | `(auth)/_layout` redirects to HQ when signed in |
| `/(app)/(tabs)/home` | HomeScreen ("HQ") | Tab bar: HQ / Agent |
| `/(app)/(tabs)/profile` | ProfileScreen ("Agent") | |
| `/(app)/games` | GamesScreen ("Case files") | All your operations, filterable |
| `/(app)/game/[id]` | One of the game views | Polls the engine and picks a view by state (see [client data flow](client-data-flow.md)) |

`(app)/_layout` redirects to login when signed out. Stack headers are hidden; each screen draws its own `TopBar`.

## What isn't built yet

- Push notifications (a report against you only appears when your app polls)
- Realtime updates instead of polling
- A hosted Supabase project and release builds (EAS profiles exist in `eas.json`)
- Profile editing and settings screens (buttons exist, screens don't)
- Android has not been run since the revival
